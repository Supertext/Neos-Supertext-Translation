# Changelog

## Unreleased

- Added: PHP 8.5 in the CI test matrix (the package already allows PHP 8.2 and newer). Demo: Neos SEO 4.3.0 and current Guzzle/Symfony patch releases.

- New: **Translation review** per language (Administration → Supertext → tick *Translation review* in the language's row, or `languages.<value>.review: true` in Settings.yaml): translations into that language go through Supertext's review service (Supertext Localization Review), where customers and Supertext linguists correct them on the website with a Chrome extension; corrections come back into Neos with the next translation, and texts translated before keep their (reviewed) wording. Same API key, billing, languages and messages; other languages keep going directly to Supertext. New setting `reviewUrl` (`SUPERTEXT_REVIEW_URL`; defaults to Supertext's review service, `''` turns review off everywhere). Off for every language after the update. `supertext:check` shows the review service and the languages that use it. All four interface languages.

- New: back-end module **Administration → Supertext** (administrators): one combo box per language of the site (every value of the language dimension, the source language included) with Supertext's languages (*German (Switzerland) (de-CH)*, names in the interface language) and, where the chosen language offers one, the form of address (default, formal, informal). Preselected is Supertext's suggestion (`de` → `de-DE`, `en_US` → `en-US`, `es_ES` → `es`); languages without one (`en_UK`, `en_IE`, `gsw`) show *— choose —* and stop with *has no Supertext language yet* until chosen. Choices are checked against Supertext's list and stored in the persistent cache `Supertext_NeosTranslation_State`; `languages.<value>.code` / `politeness` in Settings.yaml still work and win (shown read-only). In English, German, French and Italian; shows the package version. Nothing to migrate: existing Settings.yaml mappings keep working as they are.
- Changed: the *has no Supertext language yet* message points to Administration → Supertext. Translation files use the same mapping as translations.
- Demo: German, French and Italian are chosen in the module on the first start (`demo:ensurelanguages`); only `en_UK` stays in Settings.yaml.

- New: back-end module **Management → Supertext** for editors (and administrators): *Export for translation* (choose a page, the languages and XLIFF 1.2 or HTML, download the file) and *Import translation* (upload the translated file, optionally *Also import texts whose source changed since the export*, and see a summary per page and language). It works in the editor's own workspace, so imported translations are reviewed and published as usual, and imports run with the editor's permissions. In English, German, French and Italian, following the user's interface language. Access through `Policy.yaml` (granted to `Neos.Neos:Editor`); hide it with `Neos.Neos.modules.management.submodules.supertext.enabled: false`. Uploads up to 10 MB, never stored.

- New: Export for translation (XLIFF 1.2 or HTML) and import of translated files; Supertext SDK 0.5.0. `./flow supertext:export <node> <language>…` writes a page's (or content node's) texts for translation tools, translators or Supertext's web app; `./flow supertext:import <file> [--include-changed]` writes the translations back like a Supertext translation (missing language variants are created first) and prints a summary per language. Nothing is sent to Supertext; files up to 10 MB.
- Changed: Supertext SDK 0.4.0 defaults: a language dimension value without a mapping now uses Supertext's default where one is obvious (`de` → `de-DE`, `fr` → `fr-FR`, `en` → `en-US`, `es_ES` → `es`, `zh_TW` → `zh-Hant`) instead of failing; only values without a default (e.g. `en_UK`, `en_IE`, `gsw`) still need `languages.<value>.code`.
- Changed: version reports, the API key check result and the reachability ping now use Supertext Plugin Health 0.1.0 (bundled in `lib/supertext-plugin-health`); Supertext SDK updated to 0.3.0. No change for sites: settings and stored state stay as they are.
- **Breaking:** no guessed language codes any more. Supertext accepts only its own codes (regional only for German, English, French, Italian and Portuguese, e.g. `de-CH`; bare for the others, e.g. `es`, `nl`); the old default regions (`de` → `de-DE`, `es` → `es-ES`, `zh` → `zh-CN`) were partly rejected by the live API. Every language dimension value now needs to be a Supertext code (`en_US`, `es`) or mapped with `languages.<value>.code` (`de: { code: 'de-CH' }`, `en_UK: { code: 'en-GB' }`); otherwise translating stops before anything is sent, with *The language … has no Supertext language yet. Ask your administrator to map it …*. The same mapping is used for the source language (`de-CH` is sent as `de`).
- New: `supertext:check` lists every language dimension value with its Supertext code (or *not mapped*) and warns about a formal/informal tone set for a target that has none (Supertext answers *Supertext offers no formal or informal tone for this language …*).
- New: setting *Send version information to Supertext* (`versionReports`, on by default; `SUPERTEXT_VERSION_REPORTS=0` turns it off): sends the site URL and the versions of the package, Neos, PHP and the Supertext SDK, whether a key is set and the API key check result to Supertext after an update and when the key changes. No content, no API key, no personal data. See the installation guide.
- New: automatic API key check (Supertext's cost-free `features` call) when the key changed, on `supertext:check` (shown with its time) and after Supertext rejected the key during a translation.
- New: public `GET /supertext/ping` for the Supertext Commando Center (404 while version information is off).
- New: the API key messages (*Supertext rejected the API key*, *No Supertext API key is set*) carry the links to create a Supertext account and generate the key.
- Changed: bundled Supertext SDK 0.2.1 (`lib/supertext-sdk`, API classes now in `Sdk\V1`).
- Changed: the package now talks to Supertext through the official [Supertext SDK for PHP](https://github.com/Supertext/Supertext-API-SDK-and-Guide) instead of its own API client, HTML packer and language code rules. The SDK is bundled in the package (`lib/supertext-sdk`), so there is nothing extra to install. Same behaviour; error messages are the SDK's (e.g. *Supertext rejected the API key*), with new ones for rejected language pairs and incomplete translations.
- Fixed: a target language Supertext doesn't know is now reported as an unsupported language pair naming both languages (was: *not found*).
- Docs: interface languages. The package has no screens of its own; editors use Neos' dialogs, which follow their interface language (English, German, French, Italian and more). CLI output stays English.
- `supertext:check` prints the package version first (e.g. `Supertext Translation for Neos 0.1.0`), read from Composer at runtime.

## 0.1.0 — 2026-10-07

- First version for Neos 9: Supertext AI translation when pages and content are created in another language (Neos UI *Create and copy* / *Create empty*, `supertext:translate`).
- One Supertext request per target language and request; node-type-driven field selection; rich text kept; URL path segments rebuilt from translated titles.
- Per-language Supertext code, formality and opt-out via settings; `SUPERTEXT_API_KEY` / `SUPERTEXT_API_ENDPOINT`; retries on rate limiting.
- `supertext:check` command.
- Demo container (`demo/`): Neos 9.1 + Neos.Demo with French and Italian, accounts from `DEMO_ADMIN_*` / `DEMO_EDITOR_*`.
- Installation, user and developer guides with screenshots generated from the demo (`Tests/Docs/screenshots.mjs`).
- Links to create a Supertext account and generate the API key (Integrations → API, Admin role) in `Settings.yaml`, the missing/invalid-key messages, `supertext:check` and the docs.
